## Work Completed

### Milestone 1: Understanding Tensor Contraction Operations
- **Conceptual Clarity Achieved**: Clarified the distinctions between numpy.dot(), numpy.matmul(), numpy.inner(), and numpy.outer()
  - **numpy.inner()**: Sums over the *last* axes only (works for any shapes, uses cartesian product on non-contracted dims)
  - **numpy.dot()**: Deprecated and context-dependent (essentially same as matmul for 2D, but different for N-D)
  - **numpy.matmul()**: Standard linear algebra semantics with broadcasting on batch dimensions
  - **numpy.outer()**: Flattens inputs and computes cartesian product with no summation

- **Strategic Decision**: Prioritized implementing matmul() over dot() because:
  1. matmul() is the modern NumPy standard for matrix operations
  2. Broadcasting semantics on batch dimensions are well-defined and predictable
  3. dot() causes "cartesian explosion" when used with N-D arrays (unpredictable size growth)
  4. matmul() behavior matches standard linear algebra libraries (TensorFlow, PyTorch)

### Milestone 2: Implement tl_tensor_matmul() with Broadcasting
- **Implementation File**: `/Users/cakula/Workspace/tofu/src/tl_tensor_matmul.c`
- **Key Features**:

  2. Extract batch dimensions and compute broadcast dimensions
  3. Compute output shape based on batch broadcast + matrix shapes
  4. Iterate over all batch combinations
  5. For each batch, perform standard matrix multiplication
  6. Handle output indexing based on squeeze flags (when 1-D inputs consumed dimensions)

## Technical Context

### Architecture Decisions

#### 1. Matrix Multiplication Strategy
**Decision**: Use broadcasting on batch dimensions instead of cartesian product
**Rationale**:
- Broadcasting matches NumPy semantics and modern deep learning frameworks
- Predictable output size: batch_size × m × p (not exponential like dot product)
- Aligns with how batch operations work in deep learning
- More intuitive for tensor operations

**Implementation**: Treat all dims except last 2 as batch dims, broadcast these, then apply standard MM to last 2

#### 2. Dimension Handling for 1-D inputs
**Decision**: Temporary reshape to handle edge cases
**Rationale**:
- Keeps core algorithm simple (always works on ≥2-D tensors)
- Proper squeeze semantics: [n] @ [n] → scalar, but [n] @ [m,n] → [m]
- Temporary tensors cleaned up immediately after computation

#### 3. Outer Product as Flattening Operation
**Decision**: Flatten both inputs instead of preserving structure
**Rationale**:
- Matches NumPy's outer() behavior
- Simpler implementation (no need to track dimensions)
- Clear semantics: always produces 2-D output
- Different from inner/matmul (which preserve structure)

### Design Patterns Used
- **Broadcasting Pattern**: Align and compute dimensions before iteration, handle mismatches with stride=0
- **Stride Computation**: Calculate element offsets for batch broadcasting dynamically
- **Batch Processing**: Iterate through batch combinations using index decomposition
- **Temporary Resources**: Create and cleanup temporary tensors for dimension adjustment

## Important Notes

### Critical Implementation Details

1. **Broadcasting Stride Computation** (matmul lines 164-190):
   - For each batch dimension, check if it's actually present in the tensor
   - If dimension is 1 or missing: stride = 0 (broadcast behavior)
   - If dimension > 1: stride = product of all subsequent dimensions
   - This allows efficient offset computation without explicit expansion

2. **Squeeze Semantics** (matmul lines 73-75, 236-248):
   - When 1-D input consumed to make it 2-D, remember this with squeeze flag
   - Output indexing must account for squeeze (omit dimension if squeezed)
   - Critical for correct output shape: [n] @ [n,m] should give [m] not [1,m]

3. **Outer Product Flattening** (outer lines 46-47):
   - Uses tensor->len (total elements), not dims
   - Treats 2-D [2,3] as flat [6], enabling cartesian product behavior
   - Different from inner/matmul which preserve structure

### Gotchas & Warnings

1. **Broadcasting Not Automatic**: Don't assume matmul() will automatically broadcast incompatible dimensions. It follows NumPy rules: mismatch only allowed if one dimension is 1.

2. **Outer Product Destroys Structure**: outer([2,3] @ [4,5]) gives [6,20], not [2,3,4,5]. It flattens. This is intentional and matches NumPy.

3. **Dimension Ordering**: matmul contracts on last 2 dimensions. Broadcasting happens on all other dimensions. Keep this distinction clear.

4. **Temporary Tensor Cleanup**: In matmul, a_temp and b_temp must be freed even on error paths (currently done with cleanup before errno returns).
