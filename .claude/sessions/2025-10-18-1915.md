## Technical Context

### Architecture & Design Decisions

#### Inner Product Implementation Strategy
- **Decision**: Use cartesian product semantics for non-last dimensions (NOT broadcasting)
- **Rationale**: NumPy's `inner()` function does NOT broadcast non-last dimensions; it performs a cartesian product instead
- **Example**: `inner([2,3], [2,3])` produces `[2,2]` not `[2,3]`
  - This is fundamentally different from matrix multiplication where non-last dims would broadcast
  - NumPy treats inner product as: "sum over last axis of each vector pair in cartesian product of all other vectors"

#### Output Shape Calculation
- **Formula**: `output.shape = src1.shape[:-1] + src2.shape[:-1]`
- **Examples**:
  - `[3] × [3]` → `[] + [] = scalar` (handled as special case)
  - `[2,3] × [2,3]` → `[2] + [2] = [2,2]`
  - `[2,3,4] × [5,4]` → `[2,3] + [5] = [2,3,5]`

#### Cartesian Product Implementation
- Uses stride-based indexing to map output coordinates to input indices
- Splits output coordinates: first `src1_trunc_ndim` for src1, last `src2_trunc_ndim` for src2
- For each output position, computes inner product of corresponding input vectors
- Memory-efficient: operates on coordinates and strides rather than expanding full cartesian product

### Design Patterns Used
1. **Stride-based indexing**: Maps multi-dimensional coordinates to linear memory indices
2. **Element-wise function dispatch**: Uses `tl_elew_func` for data-type-agnostic operations
3. **Test-driven validation**: Comprehensive test coverage with explicit expected values
4. **Ground truth validation**: Python NumPy scripts validate C implementation correctness

```c
/* Compute the output shape: concatenate shapes without last dimensions */
int src1_trunc_ndim = src1->ndim - 1;
int src2_trunc_ndim = src2->ndim - 1;
int out_ndim = src1_trunc_ndim + src2_trunc_ndim;
int out_dims[TL_MAXDIM];

// Copy src1's dimensions (except last)
for (int i = 0; i < src1_trunc_ndim; i++) {
    out_dims[i] = src1->dims[i];
}

// Append src2's dimensions (except last)
for (int i = 0; i < src2_trunc_ndim; i++) {
    out_dims[src1_trunc_ndim + i] = src2->dims[i];
}
```

#### Cartesian Product Computation (tl_tensor_inner.c, lines 132-168)
```c
// For each position in the output
for (int di = 0; di < dst->len; di++) {
    // Get coordinates in the output tensor
    tl_tensor_coords(dst, di, dst_coords);

    // Split coordinates into src1 and src2 parts
    int base_idx1 = 0;
    for (int j = 0; j < src1_trunc_ndim; j++) {
        base_idx1 += dst_coords[j] * src1_strides[j];
    }

    int base_idx2 = 0;
    for (int j = 0; j < src2_trunc_ndim; j++) {
        base_idx2 += dst_coords[src1_trunc_ndim + j] * src2_strides[j];
    }

    // Initialize sum for the inner product
    memset(inner_sum, 0, dsize);

    // For each element along the last dimension
    for (int k = 0; k < last_dim1; k++) {
        int full_idx1 = base_idx1 * last_dim1 + k;
        int full_idx2 = base_idx2 * last_dim2 + k;

        // Compute element-wise product and accumulate sum
        elew(tl_padd(src1->data, full_idx1, dsize),
             tl_padd(src2->data, full_idx2, dsize),
             elew_prod, TL_MUL);
        elew(elew_prod, inner_sum, inner_sum, TL_SUM);
    }

    // Store result
    tl_passign(dst->data, di, inner_sum, 0, dsize);
}
```

## Important Notes & Key Insights

### Critical Insight: Inner Product ≠ Broadcasting
The most important realization from this work:
- NumPy's `inner()` does NOT broadcast non-last dimensions
- Instead, it performs a cartesian product over all non-last dimensions
- This is fundamentally different from matrix multiplication (`@` operator)
- Example demonstrating the difference:
  ```
  # These would broadcast with matrix multiplication:
  a = np.arange(6).reshape(2, 3)  # shape [2, 3]
  b = np.arange(12).reshape(3, 4)  # shape [3, 4]
  result = a @ b  # shape [2, 4] - broadcasting on non-last dims

  # But inner product does NOT broadcast:
  c = np.arange(6).reshape(2, 3)  # shape [2, 3]
  d = np.arange(6).reshape(2, 3)  # shape [2, 3]
  result = np.inner(c, d)  # shape [2, 2] - cartesian product, not broadcasting!
  ```
