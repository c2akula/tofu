## Technical Context

### Architecture Decisions
1. **Error Handling Strategy**:
   - Uses `errno` for error codes (EINVAL for invalid arguments)
   - `tl_warn_ret()` macro for debug logging
   - Returns NULL for failed operations
   - Rationale: Standard C error handling pattern, no exceptions

2. **Broadcasting Implementation**:
   - Explicit broadcasting before operation (not implicit)
   - Validates broadcastability before processing
   - Rationale: Clear error messages, early detection

3. **API Design**:
   - Optional pre-allocated destination parameter
   - Consistent function signatures across operations
   - Rationale: Flexibility for memory optimization, familiar NumPy-like interface

### Design Patterns Used
1. **Three-parameter operation pattern**:
   - `tl_tensor *op(const tl_tensor *src1, const tl_tensor *src2, tl_tensor *dst)`
   - Allows in-place or new allocation

2. **Broadcasting Check Pattern**:
   - `tl_tensor_isbroadcastable(t1, t2)` returns 1/0
   - Used in element-wise and batch operations

3. **Error Message Pattern**:
   - Detailed `snprintf()` formatting
   - Includes actual dimension values for debugging
   - Written via `tl_warn_ret()` before returning NULL

```c
    for (int i = 0; i < 20; i++) b_data[i] = i + 1;

    /* [3,2,2] @ [5,2,2] - batch dimensions 3 and 5 cannot broadcast */
    tl_tensor *a = tl_tensor_create(a_data, 3, (int[]){3, 2, 2}, TL_FLOAT);
    tl_tensor *b = tl_tensor_create(b_data, 3, (int[]){5, 2, 2}, TL_FLOAT);

    errno = 0;
    tl_tensor *result = tl_tensor_matmul(a, b, NULL);

    ck_assert_ptr_null(result);
    ck_assert_int_eq(errno, EINVAL);

    tl_tensor_free(a);
    tl_tensor_free(b);
}

```
