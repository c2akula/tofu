### Milestone 1: Memory Leak in Operation Node Values (Fixed)
- **Issue**: Operation nodes allocated tensor values that were never freed, causing memory leaks in training loops
- **Root Cause**: `tl_graph_node_free()` incorrectly assumed operation values would be freed externally
- **Impact**: Each operation leaked one tensor per iteration; 100 iterations × 4 ops = 400 leaked tensors
- **Fix Applied**: Updated `tl_graph_node_free()` to properly free operation node values
  - Only INPUT and PARAM node values are user-owned
  - All other operation nodes own their value tensors and must free them
- **Files Affected**: `src/tl_graph.c`
- **Commit**: 9523ef9 - "Fix memory management and build system issues"
- **Testing**: Fixed ViT test now completes 50 epochs without memory issues

### Milestone 2: Graph Accumulation in Training Loops (Fixed)
- **Issue**: Each training iteration created new operation nodes that were never removed
  - Iteration 0: 3 nodes
  - Iteration 1: 5 nodes
  - Iteration 100: 203 nodes (exponential growth)
- **Impact**: Backward pass performance degraded as training progressed; higher memory footprint
- **Solution**: Implemented `tl_graph_clear_ops()` function
  - Keeps INPUT and PARAM nodes (user data, reusable)
  - Removes all operation nodes after each iteration
  - Graph size remains constant throughout training
- **Implementation**:
  ```c
  void tl_graph_clear_ops(tl_graph* g) {
      int write_idx = 0;
      for (int read_idx = 0; read_idx < g->num_nodes; read_idx++) {
          tl_graph_node* node = g->nodes[read_idx];
          if (node->op == TL_OP_INPUT || node->op == TL_OP_PARAM) {
              g->nodes[write_idx++] = node;
          } else {
              tl_graph_node_free(node);
          }
      }
      g->num_nodes = write_idx;
  }
  ```
- **Usage Pattern**:
  ```c
  for (int iter = 0; iter < num_iterations; iter++) {
      // Forward pass creates operation nodes
      tl_graph_node* y = tl_graph_matmul(g, x, w);
      tl_graph_backward(g, y);
      tl_graph_clear_ops(g);  // Clear ops, keep INPUT/PARAM
  }
  ```
- **API Addition**: New function `tl_graph_clear_ops()` exported in `tl_graph.h` line 101

### Milestone 4: Double-Free Bug in View Operations (Fixed)
- **Issue**: View operations (reshape, transpose) were causing double-free crashes
- **Root Cause**: View operations share data with source tensor but are marked as owners
  - When freed, they attempted to free already-freed data from the source tensor
- **Technical Details**:
  - Reshape/transpose create new tensor metadata but point to same data
  - They set a `owner` pointer to indicate data is shared
  - Previous code didn't check this flag when freeing
- **Fix Applied**: Check tensor->owner before freeing data
  ```c
  if (node->value && node->op != TL_OP_INPUT && node->op != TL_OP_PARAM) {
      if (node->value->owner) {
          /* This is a view (reshape/transpose) - only free tensor struct */
          tl_tensor_free(node->value);
      } else {
          /* This allocates its own data - free everything */
          tl_tensor_free_data_too(node->value);
      }
      node->value = NULL;
  }
  ```
- **Files Affected**: `src/tl_graph.c` (tl_graph_node_free function)
- **Commit**: 7238711 - "Fix memory leak for view operations and improve ViT test"
- **Impact**: Critical fix enabling reshape/transpose in complex architectures like ViT

## Technical Context

### Architecture Decisions
1. **Graph Lifecycle**: Nodes are added to graph once, operation nodes cleared between iterations
2. **Memory Ownership**: INPUT/PARAM nodes don't own data (user managed), operation nodes own their outputs
3. **View Operations**: Share underlying data with source, only free tensor metadata not data
4. **Training Loop Pattern**: Create graph once, call tl_graph_clear_ops() each iteration

## Code Context

### Key Functions Modified

#### tl_graph_node_free() - Memory deallocation
```c
static void tl_graph_node_free(tl_graph_node* node)
{
    if (!node)
        return;

    /* Free gradient if it exists */
    if (node->grad) {
        tl_tensor_free_data_too(node->grad);
        node->grad = NULL;
    }

    /* Free inputs array */
    if (node->inputs) {
        free(node->inputs);
        node->inputs = NULL;
    }

    /* Free backward context if it exists */
    if (node->backward_ctx) {
        free(node->backward_ctx);
        node->backward_ctx = NULL;
    }

    /* Free value tensor for operation nodes only
     * - For INPUT/PARAM nodes, value is owned by user
     * - For operation nodes, value is allocated by the operation
     * - For view operations (reshape, transpose), check owner flag
     */
    if (node->value && node->op != TL_OP_INPUT && node->op != TL_OP_PARAM) {
        if (node->value->owner) {
            /* This is a view (reshape/transpose) - only free tensor struct */
            tl_tensor_free(node->value);
        } else {
            /* This allocates its own data - free everything */
            tl_tensor_free_data_too(node->value);
        }
        node->value = NULL;
    }

    free(node);
}
```

#### tl_graph_clear_ops() - Training loop cleanup
```c

{

    int write_idx = 0;

        }

```

### Gotchas & Warnings
1. **View operations**: Reshape/transpose create new tensor metadata but share data
   - Do NOT free data pointer when view tensor is freed
